# 인계 문서 (2026-11-16)

이 문서는 PC에서 진행하던 작업을 태블릿(리눅스)에서 이어받는 에이전트를 위한 것입니다. 지금까지 확인한 사실과 기기 상태, 절차, 남은 일을 정리했습니다. ✔는 실측으로 확인한 것이고, (추정)은 확인하지 않은 판단입니다.

기기에만 있는 개인 설정(글꼴, 입력기, 오디오 등)은 저장소에 넣지 않았습니다. 이 내용은 태블릿의 `~/HANDOFF-local.md`에 따로 적었습니다.

## 1. 기기 개요

- **기기:** Lenovo TB710FU(Xiaoxin Pad Pro GT, SM8650)입니다. 컷칩이라 CPU1과 CPU2가 없고, `psci: failed to boot CPU1/2 (-22)`는 정상입니다. 램은 약 7 GB입니다.
- **부트로더:** 잠금 상태입니다. fastboot의 flash/boot 명령은 거부됩니다.
- **서명:** 커스텀 이미지는 모두 AOSP testkey로 서명합니다(`build/testkey_rsa4096.pem`, 공개키 sha1은 2597c218…). verifiedbootstate는 green입니다.
- **안드로이드(슬롯 a):** ZUI 17.5.04.070 ROW 순정입니다.
  - 암호화를 해제해 `ro.crypto.state=unsupported` 상태입니다(fstab.qcom을 패치한 vendor_a와 vbmeta_a를 재서명). → [userdata.md](userdata.md)
  - 루트는 **LTBox KernelSU LKM**입니다(init_boot_a 패치).
  - **LTBox의 Unroot는 절대 쓰지 마세요.** 예전 vbmeta를 되돌려서 vendor가 깨집니다.
  - **LTBox의 GKI 모드도 쓰지 마세요.** boot_a 커널을 바꿔서 kShimC를 덮어씁니다.

리눅스 쪽 구성:
- **커널:** 7.2.6-tb710fu입니다. ArmadaOS Freedom b75a6d48에 오버레이 `kernel/armada-overlay/tb710fu-locked`를 얹은 것이고, CI 런 43799637253(fd9e0a2)에서 빌드했습니다.
- **커널 cmdline:** DTB의 `/chosen`에 들어 있습니다.
  `root=PARTLABEL=userdata tb710fu.rootdir=/linux rw rootwait clk_ignore_unused pd_ignore_unused regulator_ignore_unused console=tty0 panic=10 tb710fu.wait=30 cpuidle.governor=teo tb710fu.kshim=1`
- **루트:** `/dev/sda14`(userdata, f2fs)의 `/linux`이고, 안드로이드 쪽에서 보면 `/data/linux`입니다. 안드로이드 `/data` 전체는 root만 `/mnt/.android/data`(0700)로 볼 수 있습니다. 리눅스 사용자 bmk의 uid 1000이 안드로이드의 system과 같기 때문에 이렇게 막았습니다.
- **리눅스는 userdata를 fsck하지 않습니다.** f2fs 커널 로그의 "quota file may be corrupted"는 리눅스가 마운트하기 전부터 있던 표시입니다.

### 부트 이미지 만들기와 쓰기

```bash
# WSL에서 (~/tb710fu/build는 Windows 저장소를 가리키는 심볼릭 링크)
RUN=<kernel.yml 런 ID> bash build/build.sh kernel      # CI 커널 받기 (out/kernel-armada)
bash build/build.sh initramfs                          # rootfs-latest 릴리스의 initramfs
ROOT_DEV=userdata KBPACK=1 bash build/build.sh kshim   # out/kshim/boot_a.img (96 MiB, AVB 검증 포함)
```

기기에서 쓰는 방법:
- **리눅스에서(root):** `dd if=boot_a.img of=/dev/disk/by-partlabel/boot_a bs=4M conv=fsync` 후 `sha256sum`으로 다시 읽어 확인합니다.
- **안드로이드에서:** adb로 이미지를 올린 뒤 `su -c dd`로 같은 방식으로 씁니다.
- **새 커널을 넣을 때는 모듈도 같이 바꿔야 합니다.** `out/kernel-armada/lib/modules/7.2.6-tb710fu`를 기기의 `/usr/lib/modules/`에 넣고 `depmod`를 실행합니다. 버전 문자열이 같아서 섞여도 경고가 나오지 않습니다.
- **EDL(최후 수단):** `adb reboot edl`로 들어가고, LTBox v2.5.4 tools(QSaharaServer, fh_loader)를 PowerShell에서 씁니다. 프로그래머는 ROM의 `xbl_s_devprg_ns.melf`입니다. 파티션 오프셋(4K 섹터)은 다음과 같습니다.
  - LUN0: super 9608, vendor_a는 super+2842368, metadata 4990376, userdata 5105064
  - LUN4: boot_a 112006(24576), vbmeta_a 136634, init_boot_a 340102, vbmeta_b 479082, vendor_boot_b 624118

## 3. 절대 규칙 (사고에서 배운 것)

1. **검증된 이미지만 쓰세요.** 새 이미지는 사용자의 명시적 동의를 받은 뒤에만 씁니다.
   - 2026-11-16에 시험하지 않은 `v4 bounce` 이미지를 슬롯 b에 썼다가, ABL 재시도 7회 동안 루프에 빠졌습니다.
2. **슬롯 b를 리눅스에서 썼다면 반드시 `qbootctl -s b`로 다시 표시하세요**(`tb710fu-update-slot-b`).
   - 슬롯이 "성공"으로 표시된 채 리셋 루프에 빠지면 ABL이 다른 슬롯으로 넘어가지 않습니다.
3. **L8B(키보드 전원)는 부팅할 때 켜지 마세요.**
   - `regulator-boot-on`에 3.304 V를 걸었다가 부팅 0.37초에 리셋됐습니다(2026-11-15).
   - 지금은 3.296 V이고, 키보드가 연결돼 있을 때만 켭니다.
4. **USB-C가 호스트 모드(OTG)인 상태에서 리셋하지 마세요.**
   - ADSP가 꺼지면 PMIC의 USB 입력이 막혀서, 충전도 EDL도 안 됐습니다.
   - 복구는 배터리를 완전히 방전시킨 뒤 충전기를 꽂고 Power+Vol−를 10분 누르는 방법(S3)으로 했습니다. → README의 사고 기록
5. **위험한 시험은 kShimC 메뉴에서 리눅스를 골라서 하세요.** 리셋되면 안드로이드로 돌아오고 루프에 빠지지 않습니다.
6. **ADSP를 강제로 재시작하는 일은 피하세요.** ADSP에는 충전기, 오디오, 센서가 다 들어 있습니다.

## 4. 기능별로 알아낸 것

### 키보드 팩

- **프로토콜:** UART 921600, 스크램블된 프레임입니다. → [keyboard.md](keyboard.md)
- **전원:** L8B를 3.296 V로 켭니다. `--vdd-test` 통과 ✔
- **커널 드라이버 `tb710fu-kbpack`:**
  - `kernel/tb710fu-kbpack/`에 있고, out-of-tree 모듈로 kernel.yml에서 빌드합니다. 코덱은 `codec-test.c`로 검사합니다.
  - DT 노드 `uart7/keyboard`는 기본이 disabled입니다. `KBPACK=1`로 빌드하면 켜집니다.
  - 기기에서 실측한 결과 ✔: 부팅 6.7초에 probe되고, 키와 터치패드가 동작하고, 리셋은 없었습니다.
- **연결 감지:** gpio81(low = 연결)이고, gpio-keys가 `SW_DOCK`으로 보냅니다. 드라이버는 input handler로 이 신호를 따라갑니다.
- **뒤로 접었을 때:** 펌웨어가 키와 터치패드를 모두 끕니다 ✔. 이때 `SW_TABLET_MODE=1`이 나옵니다.
- **덮었을 때:** 이때도 `SW_TABLET_MODE=1`이 나오고, 0/1이 수십 번 튑니다 ✔. 그래서 덮은 것과 접은 것을 이 신호만으로는 구분할 수 없습니다.
  - **남은 일:** 덮을 때 절전하는 기능입니다. 후보 방식은 조도 센서와 묶는 것인데, 조도 값은 아직 기록하지 못했습니다(monitor-sensor 출력 버퍼링 때문).
  - 열 때 깨우려면 UART나 gpio81을 wakeup 소스로 등록해야 합니다(드라이버 작업).
- **Caps Lock LED가 순정보다 어둡습니다.** 전원은 HPM, 3.296 V로 순정과 같습니다. 원인은 모릅니다(펌웨어 명령 차이일 수 있음, 추정).

### 센서 (회전·조도)

- **구조:** BMI3xx(가속도·자이로)와 STK6B9x(조도)가 ADSP SSC 뒤에 있습니다. hexagonrpcd(sensorspd) → libssc → iio-sensor-proxy → KWin 순서로 연결됩니다.
- **`sns_reg.conf`:** 반드시 **순정 vendor `/etc/sensors/sns_reg_config` 그대로**여야 합니다(DSP 쪽 경로). → `build/rootfs-files/sns_reg.conf`
- **hexagonrpcd 패치(`build/rootfs-files/hexagonrpcd-registry-write.py`):**
  - 이 기기의 센서 PD는 부팅할 때 registry를 씁니다(`DIR`, `fstempfile` 후 이름 변경, `sns_reg_version`, `parsed_file_list.csv`). 안드로이드에서는 sscrpcd가 persist를 읽기·쓰기로 열어 줍니다.
  - upstream hexagonrpcd는 읽기 전용이라 패치로 쓰기를 넣었습니다: fwrite, frename, fremove, mkdir, ftrunc, fsync.
  - persist의 `sensors/registry` 디렉터리 전체를 `P/sensors/persist-registry`(fastrpc 소유)로 연결합니다.
  - 리스너의 입력 버퍼를 64 KiB로 늘렸습니다.
- **iio-sensor-proxy 패치(`iio-sensor-proxy-claim-race.py`):** KWin이 SSC 드라이버가 열리기 전에 가속도계를 요청하면 센서가 켜지지 않던 문제를 고쳤습니다.
- **보정 행렬:** `0,1,0;-1,0,0;0,0,1`. 정면으로 든 가로 상태에서 normal로 나옵니다 ✔
- **절전 훅(`/usr/lib/systemd/system-sleep/tb710fu-sensors`):** 절전 전에 proxy를 멈추고, 깨어난 뒤 hexagonrpcd와 proxy를 다시 켭니다. hexagonrpcd 유닛에 `Conflicts=suspend.target`이 있어서 필요합니다.
- **iio-sensor-proxy 크래시:** 한 번 SIGSEGV로 죽었습니다. 위치는 libssc의 `report_received`(handle_report ← report_large_received)이고, 원인은 미분석입니다. 대응으로 `Restart=always` drop-in을 넣었습니다.
- **근접·나침반:** SSC가 내놓지 않습니다.

### 전원과 배터리

- **충전 표시:** ADSP가 배터리 `current_now`를 반대 부호로 보냅니다(방전 +, 충전 −). 그래서 upower가 충전을 방전으로 표시했습니다. → `kernel/armada-overlay/tb710fu-locked/patches/0001-qcom-battmgr-tb710fu-current-sign.patch`. 새 커널에서 방전 −0.94 A, upower discharging으로 확인했습니다 ✔
- **충전 상한:** 80%(재시작 70%)로 잡혀 있습니다. ADSP에 남아 있는 안드로이드 배터리 보호 설정으로 보입니다(추정).
- **PC의 USB 포트로는 충전되지 않습니다.** PD 충전기를 쓰면 8.46 V, 약 36 W로 들어갑니다.
- **절전:** s2idle은 동작합니다 ✔. RTC 깨우기 20초 시험과 전원 버튼 재우기·깨우기를 확인했습니다. deep은 커널 기본값이지만 시험하지 않았기 때문에 `/etc/systemd/sleep.conf.d/tb710fu.conf`에서 `MemorySleepMode=s2idle`로 고정했습니다(기기 로컬 설정).
- **유휴 전력:** 화면을 켠 채 놀 때 1.0~1.4 A입니다. 밝기를 100%에서 10%로 내려도 약 0.2 A만 줄었습니다.
  - **원인 1:** Armada가 스피커 PCM을 계속 켜 두도록 설정했습니다(`53-lenovo-tb710fu-speakers.conf`의 `suspend-timeout=0`). 이 때문에 ADSP glink 인터럽트가 초당 146회 나왔습니다. 기기에서는 사용자 설정으로 10초 뒤 끄게 했고, 0회로 줄었습니다. 앰프가 TDM 클럭에 동기화하지 못할 위험이 있습니다.
  - **원인 2:** plasmashell이 초당 약 140회 깨어납니다. 패널 위젯이 원인으로 보입니다(추정, dwell clicker 의심).
  - **원인 3:** CPU 클러스터 전원이 거의 꺼지지 않습니다. TEO governor를 넣었지만 효과는 아직 재지 않았습니다.
- **power-profiles-daemon:** 플랫폼 드라이버가 placeholder라서 절전 프로필로 바꿔도 실제 클럭은 바뀌지 않습니다.

### 기타

- **pacman:** 커널에 Landlock이 없어서 `DisableSandboxFilesystem`이 필요합니다(build.sh에 반영).
- **파일 관리자:** UFS 파티션 숨기기(`UDISKS_IGNORE`)를 build.sh에 반영했습니다.
- **FEX/Steam:** 보류했습니다. Arch ARM 패키지가 없어서 소스 빌드가 필요합니다. 미완료이고, `/var/tmp/FEX`에 클론만 남아 있습니다.

## 6. 남은 일 (우선순위 순)

1. **키보드를 덮을 때 절전:** 조도 값을 실측하고(덮었을 때와 뒤로 접었을 때), `SW_TABLET_MODE` 디바운스와 조도를 묶은 규칙을 만듭니다. 열 때 깨우려면 드라이버에서 wakeup 소스를 등록해야 합니다.
2. **iio-sensor-proxy/libssc 크래시 원인:** `report_received`를 보고, 필요하면 libssc 0.4.4 대신 고정 커밋으로 빌드합니다.
3. **유휴 전력:**
   - TEO 효과를 잽니다. 배터리 상태에서 전류를 재고, `pm_genpd` 클러스터 idle을 봅니다.
   - plasmashell이 계속 다시 그리게 만드는 위젯을 찾습니다.
   - 스피커 절전 설정이 앰프 문제를 일으키는지 지켜봅니다.
4. **Caps Lock LED가 어두운 원인:** 안드로이드에서 UART를 캡처해 비교합니다.
5. **deep 절전 시험:** kShimC에서, USB-C를 비운 상태로 합니다.
6. **SSD 이미지 쓰기:** 보류 중입니다. 사용자 결정을 기다립니다.
7. **FEX/Steam:** 보류 중입니다.
8. **커널 쪽 남은 정리:** `qcom_battmgr` 부호 패치를 upstream 방식(DT 속성)으로 바꿀지 검토합니다.

- **증상**(태블릿 세션의 분석 ✔ 로그):
  - 키보드를 뒤로 접는 중에 gpio81(SW_DOCK)이 0.44초 동안 끊겼습니다.
  - 그러자 드라이버가 바로 detach해서, 키보드가 핀에 붙어 있는 채로 L8B를 껐습니다.
  - 그 뒤 26초 동안 입력이 멈췄고(화면은 켜져 있었음), 다시 붙이는 순간 리셋됐습니다.
  - pstore에는 아무것도 남지 않았습니다.
- **원인 추정:** 전원이 꺼진 키보드가 RX를 Low로 붙잡아서, GENI UART가 끝없는 break 인터럽트를 받은 것으로 봅니다(추정).
- **수정**(커밋 60b3bca, 태블릿 세션이 작성):
  - SW_DOCK을 1초 디바운스합니다.
  - UART는 VDD가 켜진 동안에만 엽니다. 붙일 때는 VDD → 50 ms → open 순서이고, 뗄 때는 close 후 VDD를 끕니다.
- **주의: 모듈은 반드시 CI(kernel.yml)에서 빌드하세요.**
  - 태블릿에서 다른 커널 트리로 빌드한 모듈은 `struct module` 크기가 달라 로드가 거부됐습니다(Exec format error).
  - vermagic이 같아도 이렇게 거부될 수 있습니다.
- **새로 발견한 것(미해결):**
  - **ADSP `q6v5 ready/handover` 인터럽트 폭주:** "Handover signaled, but it already happened"가 초당 약 5회 나옵니다. 스피커 재생이 시작된 때(1590초)부터 시작됐고, 직전 부팅에서는 2초부터 계속됐습니다. 오디오 경로와 관련이 있어 보입니다(추정). 전력 낭비 가능성이 있습니다.
  - **iio-sensor-proxy 세그폴트:** 한 부팅에서 6번 났습니다(libssc `report_received`). 설치된 libssc는 ALARM 0.4.4 패키지 파일 위에 고정 커밋(033e2a3) 빌드를 덮어쓴 것입니다(`pacman -Qkk`에서 50개 파일 변경). ALARM의 iio-sensor-proxy 3.9는 이미 libssc 지원을 포함하고 있으니, 우리 빌드 대신 패키지를 쓰는 것도 검토할 만합니다(경합 수정은 필요).
